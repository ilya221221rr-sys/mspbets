# MSPBETS — большое обновление: что добавлено и что где менять

> **Render, Turso и Python остались прежними.** Хостинг, база и язык не менялись.
> Новые таблицы создаются командами `CREATE TABLE IF NOT EXISTS`, старые данные игроков
> не удаляются и не переписываются. Добавлены только 2 безопасные колонки
> (`skins.weight`, `cases.active`) с значениями по умолчанию.

## 1. Как выкатить (5 минут)

1. Распакуйте архив `mspbets-update.zip` **поверх вашего репозитория** `ilya221221rr-sys/mspbets`
   (файлы `app.py`, `web/index.html`, `web/app.js` заменятся, остальное добавится).
   `web/style.css`, `render.yaml`, `requirements.txt`, `.python-version` **не менялись**.
2. Закоммитьте и запушьте в GitHub (через GitHub Desktop или «Add file → Upload files»).
3. Render сам пересоберёт сервис. При первом старте бэкенд создаст новые таблицы
   и засеет 6 новых кейсов (54 скина). Логи покажут `extras запущены`.
4. Откройте бота → мини-приложение. Готово.

**Что нужно/можно задать в Render → Environment (все необязательны):**

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `FEED_ENABLED` | `1` | `0` — выключить автозагрузку матчей |
| `FEED_SYNC_MINUTES` | `20` | как часто обновлять матчи и кэфы |
| `FEED_WINDOW_HOURS` | `48` | матчи только на ближайшие N часов (загружаются) |
| `EVENTS_WINDOW_HOURS` | `48` | сколько часов вперёд матчи показываются игрокам |
| `EVENTS_CACHE_SECONDS` | `10` | кэш списка матчей на сервере |
| `DB_POOL` | `1` | пул соединений с Turso (`0` — выключить) |
| `FEED_MARGIN` | `0.06` | маржа БК (6%) — на неё урезаются кэфы источника |
| `FEED_PER_LEAGUE` / `FEED_MAX_OPEN` | `12` / `100` | лимиты матчей на лигу / всего |
| `FEED_LEAGUES` | все | список путей ESPN через запятую, напр. `soccer/eng.1,basketball/nba` |
| `FEED_BROADCAST` | `0` | `1` — рассылать всем игрокам дайджест новых матчей |
| `PANDASCORE_TOKEN` | пусто | токен pandascore.co (бесплатный) — включает Dota 2 и CS2 |

`BOT_USERNAME` уже есть в вашем `render.yaml` — он используется для реферальной ссылки.
Бот работает на **одном воркере** (как и сейчас: `uvicorn app:app`) — это важно для Краша.

## 2. Что добавлено (по вашему списку)

### Игры на баллы
* **Краш по раундам** — один общий множитель на всех, живой график, чат, лента ставок и
  кэшаутов других игроков, автовывод, WebSocket (`/ws/crash`) с запасным опросом.
  Честность: до раунда виден хеш seed, после крэша раскрывается seed
  (`crash = HMAC-SHA256(seed, "mspbets-crash")`). RTP 96%.
* **Мины** (поле 5×5, 1–24 мин, RTP 97%), **Plinko** (8–16 рядов, 3 уровня риска, RTP ≈ 96%),
  **Dice** (свой шанс 1–95%, RTP 97%), **Колесо** (50 секторов, RTP 95.8%), **Монетка** (x1.94).
* **Нарды** — короткие нарды против бота по настоящим правилам: бар, удары, дубли,
  обязательность ходов, выброс шашек. Кубики бросает сервер, партия хранится в Turso
  (не пропадает при перезапуске). Победа ×1.9.

### Кейсы и апгрейдер
* 6 собственных кейсов (150 / 500 / 1 500 / 4 000 / 10 000 / 25 000 PTS), 54 уникальных скина
  со своей графикой (`web/skins`, `web/cases`).
* У каждого предмета показан **точный шанс**, у кейса — **RTP 90–95%**
  (90 / 92 / 92 / 93 / 94 / 95). Шанс на экране = реальный: используются те же целые веса.
* **Апгрейдер:** выбираешь до 5 скинов → список целей с шансом
  `95% × цена_источника ÷ цена_цели` (комиссия 5%), шансы 4–90%. Результат по `randrange(10000)`.
* Инвентарь с массовой продажей, **коллекции** (собрал все предметы кейса — награда + достижение).

### Единый баланс и журнал
Любое движение баллов идёт через `extras/core.py → adjust()` и пишется в таблицу
`transactions` (сумма, баланс после, тип, описание). Игрок видит это в
**Профиль → Журнал операций**. Это покрывает и старый код: ставки, экспрессы, расчёт,
промокоды, ручные начисления админа.

### Ежедневный бонус, серии, уровни, VIP, задания, достижения
* Бонус 50→400 PTS по 7-дневному циклу, серия сбрасывается при пропуске, VIP даёт +25% за уровень VIP.
* XP за каждую ставку (1 XP за 5 PTS), уровни, 7 рангов (Новичок → Легенда), VIP с 20 уровня,
  рамки аватара по рангам, бейджи из достижений.
* Закрытые турниры недели: «Недельный забег» (все), «Золотой кубок» (с 20 ур.), «Алмазный клуб» (с 45 ур.).
  Очки = сумма ставок за неделю, призы топ-3 (50/30/20%) выплачиваются автоматически.
* Ежедневные задания (всегда «Поставь на 3 матча» и «Выиграй экспресс» + 2 случайных), 25 достижений.

### Рефералка (защита от накруток)
Ссылка `t.me/<бот>?start=ref_<id>`. Друг привязывается только если он **новый** игрок и
ещё не ставил; бонус (50 000 тебе / 30 000 другу) выдаётся **только после 5 ставок на 500+ PTS**,
один раз, не более 100 выплат на пригласившего, самореферал отсекается.

### Социальное
Публичные профили (клик по игроку в рейтинге/ленте), лента ставок на открытые матчи и
**копирование ставки** по текущему кэфу, настройка «скрыть мои ставки».

### Уведомления в бота
* «✅ Ставка сыграла / ❌ не сыграла / 🚀 экспресс сыграл / ↩️ возврат» — при любом расчёте,
  ручном и автоматическом;
* «📈 Коэффициент вырос» — кнопка 🔔 на карточке матча, срабатывает при росте от 3%;
* результаты турниров, рефералка, копирование ваших ставок.
Игрок может выключить уведомления в профиле.

### Автозагрузка матчей и коэффициентов
`extras/feed.py`. Источник — ESPN (без ключа и регистрации): футбол (АПЛ, Ла Лига, Серия A,
Бундеслига, Лига 1, ЛЧ, ЛЕ), NBA, NHL. Берутся реальные рыночные линии, переводятся в десятичные
кэфы, убирается маржа источника и накладывается ваша (6%). Каждые 20 минут: новые матчи,
обновление кэфов, закрытие приёма в момент начала, **автоматический расчёт** по итоговому
счёту (отмена/перенос → возврат ставок). Ручные матчи админа не затрагиваются.
Для **Dota 2 / CS2** добавьте `PANDASCORE_TOKEN`: расписание берётся оттуда, кэфы считаются
по рейтингу Эло из последних матчей (у бесплатного PandaScore нет линий букмекеров).
В админке появился блок «Автозагрузка матчей» со статусом и кнопкой «Синхронизировать сейчас».

## 3. Что изменено в старом коде (важно прочитать)

| Что | Как стало | Почему |
|---|---|---|
| Старые кейсы (Dota, imgur) | скрыты (`cases.active=0`), скины в инвентарях игроков **сохранены** и продаются | у них не было нормальных шансов и RTP |
| «Подкрутка» из админки (`forced_skin_id`, `custom_upgrade_chance`) | **удалена из интерфейса и из логики**; таблица `user_settings` осталась, но не читается | требование «шанс на экране = реальному» |
| `/api/crash/play`, `/api/cases/open`, `/api/upgrade`, `/api/inventory*` | заменены на `/api/v2/...` | честная математика и журнал |
| Ставка с отрицательной суммой | **баг:** увеличивала баланс. Теперь запрещено | безопасность |
| Экспресс с одним матчем дважды | **баг:** множил кэф. Теперь запрещено | безопасность |
| Ставки на уже начавшийся матч | запрещены, если у матча задан `starts_at` | как в БК |
| Расчёт матча | повторный расчёт запрещён; добавлен исход «Возврат» | защита от двойных выплат |

Чтобы вернуть старые кейсы в БД (интерфейс их всё равно не покажет): `UPDATE cases SET active=1 WHERE id<=5;`

### Типичные правки
* **Свои кейсы/цены/RTP** — `extras/catalog.py` (`CASES`), затем `python tools/gen_art.py`,
  перезапуск. Веса пересчитаются так, чтобы RTP кейса был ровно заданным.
* **Награды/пороги** — `extras/core.py` (`QUESTS`, `ACH`, `REF_*`, `RANKS`), `extras/social.py`
  (`DAILY_CYCLE`, `TOURNAMENTS`, `PRIZE_SPLIT`).
* **Какие матчи грузить** — `extras/feed.py` (`LEAGUES`) или переменная `FEED_LEAGUES`.
* **Маржа** — `FEED_MARGIN` в Render.

## 5. Честно о том, что проверено и что нет

Проверено автотестами (`python tests/selftest.py`, 122 проверки) и прогоном интерфейса в jsdom
(45 проверок, 0 ошибок JS), на локальной libsql-базе:
журнал == баланс после всех операций; RTP всех кейсов/Plinko/колеса; частота выпадений и
апгрейдов совпадает с заявленным шансом; ставки, экспрессы, расчёт, возврат; мины; нарды
(инварианты правил на 60 случайных партиях); краш (раунды, WebSocket, чат, проверка seed);
рефералка; турниры; уведомления.
**Живой запрос к ESPN проверен**: загрузка 52 матчей с реальными кэфами и автоматический расчёт
завершённых матчей NBA/NHL по счёту.

**Не проверено на ваших боевых данных:**
* работа с **настоящим Turso** (тесты шли на локальном libsql; API идентичный, но каждый запрос к
  удалённой базе медленнее — действия могут занимать доли секунды);
* отправка в Telegram (тесты подменяют бота);
* PandaScore (нет токена) — код написан по документации, но вживую не гонялся;
* ESPN — неофициальный открытый API: он может поменять формат. Тогда матчи просто перестанут
  подгружаться, остальное продолжит работать (ошибки видны в админке).

**Ограничения:** бесплатный Render засыпает — пока сервис спит, раунды Краша не идут, а матчи не
обновляются (просыпаются при первом заходе). Если бот перезапустится посреди раунда Краша,
ставки неразыгранного раунда автоматически возвращаются.

## 5. Оптимизация производительности (анти-лаги)

**Что тормозило и что сделано**

| Проблема | Решение |
|---|---|
| Эндпоинты в `app.py` были `async def` с блокирующими запросами к Turso → **весь сервер замирал** (в т.ч. Краш и WebSocket) на время любого запроса | Все такие эндпоинты стали обычными `def` (идут в threadpool), `request.json()` читается через `req_json()` |
| На каждый запрос открывалось **новое соединение** с Turso | Пул соединений (`get_db()` → `PooledConn`): `DB_POOL=1`, `DB_POOL_SIZE=8`, `DB_POOL_IDLE=4` с. Соединение с незакоммиченной записью/ошибкой в пул не возвращается |
| `ensure_user` делал 2 записи в БД **на каждый запрос** | Записывает только при первом входе / смене имени (раз в 10 мин) |
| `/api/events` отдавал все матчи и всю историю | Игроку — только **открытые матчи ближайших 48 ч** (`EVENTS_WINDOW_HOURS`) (+ ручные матчи админа без даты), кэш 10 с (`EVENTS_CACHE_SECONDS`), сброс кэша при действиях админа. Админка: `GET /api/events?all=1` |
| Автозагрузка брала 3 дня × 9 лиг | `FEED_WINDOW_HOURS=48` — грузятся только матчи ближайших 48 ч (ESPN: 3 даты вместо 4) |
| Новости Dota 2 качались на каждый заход (блокируя сервер) | Кэш RSS на 10 минут |
| Краш: канвас перерисовывался 60 к/с с `shadowBlur`, DOM-запись каждый кадр, `getBoundingClientRect` каждый кадр | 30 к/с, запись в DOM только при изменении, разреженная кривая, без `shadowBlur`, размер канваса кэшируется |
| Plinko: все колышки рисовались заново каждый кадр | Колышки кэшируются в offscreen-canvas, шарик без `shadowBlur` |
| Колесо: перерисовывалось при каждом входе | Рисуется один раз, `will-change: transform`, тень вынесена с вращающегося канваса |
| Нарды/аватарки: бесконечные CSS-анимации (`pulse`, `hue-rotate`) на десятках элементов | Убраны |
| `backdrop-filter: blur` на липкой шапке, нижнем меню и модалках (пересчёт на каждом кадре скролла) | Заменено на непрозрачный фон |
| Карточки матчей анимировались при каждой перерисовке списка | Убрано; `content-visibility: auto` для карточек вне экрана |
| Нет сжатия, нет кэша статики | `GZipMiddleware`, `Cache-Control` для картинок (7 дней) и ETag-проверка для js/css |
| Google Fonts блокировали первую отрисовку | Подгружаются неблокирующе |
| Слабые телефоны | Автоматический «лёгкий режим» (`html.lite`): без декоративных анимаций и теней |

Если после выкладки что-то пойдёт не так с пулом — поставьте `DB_POOL=0` в Render → Environment (поведение вернётся к прежнему).
Проверка: `python tests/selftest.py` (135 проверок, включая окно 48 ч и пул).

## Правки (админка, выкуп, шапка)

* **Баллы игрокам (админка)** — исправлена ошибка `NameError: uid` в `/api/admin/give-points` (из-за неё начисление и списание всегда падали с 500).
  Теперь работает поиск по ID и по `@username` (без учёта регистра), списание больше баланса списывает остаток, а не уходит в минус.
* **Промокоды** — в админке под формой создания появился список «Мои промокоды» с кнопками ✏️ (изменить код/награду) и 🗑 (удалить).
  Эндпоинты: `GET /api/admin/promos`, `POST /api/admin/update-promo`, `POST /api/admin/delete-promo`.
* **Шапка на телефоне** — логотип больше не перекрывается чипом уровня/профиля и балансом: на узких экранах элементы сжимаются
  (скрывается подпись PTS и мини-аватар), учитывается safe-area Telegram.
* **Реферал** — награда пригласившему: **10 000 PTS** (`REF_REWARD_REFERRER` в `extras/core.py`), другу по-прежнему 150.
* **Выкуп ставки** — в карточке ставки (История) кнопка «Выкупить за N PTS» для ординаров и экспрессов, пока матч не начался.
  Цена = выплата × вероятность исхода по текущим кэфам × (1 − 7%) (`CASHOUT_MARGIN` в `extras/betting.py`);
  у экспресса уже сыгравшие события учитываются полностью. Новые колонки `predictions.cashout` и `bets.cashout` добавляются автоматически.
  Эндпоинты: `GET /api/cashout/offer`, `POST /api/cashout`. В журнале операций — тип «Выкуп ставки».
* **Карточка ставки** — после расчёта показывает по каждому событию: ✅ зашло / ❌ не зашло / ↩️ возврат / ⏳ ожидает,
  свой исход и итог матча; в списке истории — «Зашло 2 из 3».

## Слоты (демо), аватары, подпись исхода, окно 48 часов

### 🎰 Слоты — только демо
* Игры → **«Слоты · демо»** (`web/slots.js`). Плитки Pragmatic Play (Gates of Olympus, Sweet Bonanza, Sugar Rush, Big Bass…) и Hacksaw Gaming (**Le Zeus**, Le Bandit, Wanted Dead or a Wild…). Поиск и фильтр по провайдеру.
* Нажатие на плитку открывает демо **на весь экран** внутри приложения (iframe). Играют на виртуальные монеты провайдера: **PTS не списываются и не начисляются**, XP/задания/турниры не засчитываются. Закрыть — ✕ или «домой» в самом слоте. Кнопка ↗ открывает игру в браузере (запасной вариант, если Telegram что-то блокирует).
* Pragmatic: официальный демо-сервер `demogamesfree.pragmaticplay.net` (`openGame.do?gameSymbol=…`). Hacksaw: страница-обёртка `web/hacksaw.html` с официальным лаунчером `hacksaw-launcher.min.js` (`partner=demo, mode=demo`, как на hacksawgaming.com) — он сам берёт актуальную версию игры, ссылки не устаревают.
* **Добавить слот**: одна строка в массиве `SLOTS` в `web/slots.js`. Для Pragmatic нужен `gameSymbol` (проверка: ответ `openGame.do?gameSymbol=…` содержит `gname=`), для Hacksaw — `gameid` со страницы `hacksawgaming.com/games/<слаг>` (атрибут `gameid`).
* Слоты работают только пока доступны серверы провайдеров. Провайдеры могут сменить ссылки/ограничить встраивание — тогда плитка покажет пустое окно, остальное приложение не пострадает.

### 🖼️ Аватары

### 2. Три кейса с НАСТОЯЩИМИ предметами Dota 2
`extras/catalog.py → DOTA_CASES`. Картинки — оригинальные иконки предметов Steam (`web/dota/*.webp`),
обложки кейсов — `web/cases/dota_*.webp` (генерация: `node tools/gen_dota_covers.js`).

| Кейс | Цена | RTP | Что внутри |
|---|---|---|---|

* Редкость настоящих предметов считается по абсолютной цене (Common → Immortal), см. `rarity_abs`.
* Новые кейсы добавятся сами при первом старте (`cases.seed()` идемпотентен), игроков и инвентари это не трогает.

### 5. Поддержка (игрок → бот + админка → ответ)
Новый файл `extras/support.py` (+ `web/support.js`, 3 таблицы `support_*` создаются сами).
* **Игрок:** Профиль → «Поддержка» (чат; красная цифра, если есть ответ). Либо просто написать боту обычный текст.
* **Вам приходит:** сообщение в Telegram-бота (всем из `ADMIN_IDS`): номер обращения, имя, @username, ID, текст.
  И то же самое в приложении: Админ-панель → «💬 Поддержка (обращения игроков)» — список, переписка, ответ, закрытие.
* **Как ответить:**
  * в боте — сделайте *reply* на пересланное обращение, или `/reply <номер> текст`;
  * в приложении — откройте обращение и нажмите «Ответить».
  Ответ приходит игроку в бота («💬 Ответ поддержки …») и в его чат в приложении.
* `/tickets` — открытые обращения, `/close <номер>` — закрыть (игроку придёт уведомление).
* Защита: не более 8 сообщений за 10 минут от игрока, до 1500 символов, весь текст экранируется (HTML-инъекций нет).
* Переменные окружения не нужны: используются `BOT_TOKEN` и `ADMIN_IDS`, которые уже заданы на Render.
